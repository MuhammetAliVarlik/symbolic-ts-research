# F0-06 — Transition matrices per domain

Generated by `scripts/run_transition_matrices.py`, using the F0-04/F0-05 tokenisation
as-is. Transitions are counted within each series only — a series boundary (last token
of one ETT variant or ticker to the first token of the next) is never counted as a
transition.

## Method

25x25 first-order transition count matrix per domain (pooled across all 4 ETT variants
/ all 7 tickers), then row-normalised to probabilities. Zero-count **cells** are left as
explicit zeros — no smoothing — since smoothing here would hide exactly the sparse-row
problem this task exists to surface; F0-07 can decide separately whether its own
KL-divergence calculation needs smoothing, informed by the row counts below. Rows with
zero total observations (a token that never once appears as a "from" state) are left
undefined (`NaN`), not coerced into a fabricated distribution.

Outputs:
- `results/transition_matrix_ett.csv`, `results/transition_matrix_finance.csv` — the
  row-normalised 25x25 probability matrices.
- `results/transition_matrix_row_counts.csv` — observation count per row per domain,
  flagged against a minimum of 30 (a common rule-of-thumb floor for a trustworthy
  categorical estimate).
- Figures A5 (finance) and A6 (ETT), shared `[0, 1]` colour scale. Fixed bounds, not a
  data-driven max — see below for why that matters.

## Rows too sparse to trust

| domain  | from_token | observations | status |
|---------|------------|--------------|--------|
| ett     | C0_V0      | 1            | sparse |
| ett     | C4_V0      | 2            | sparse |
| finance | C0_V0      | 0            | undefined |
| finance | C4_V0      | 0            | undefined |
| finance | C4_V1      | 19           | sparse |

23/25 ETT rows and 22/25 finance rows clear the 30-observation floor. The two
finance-undefined rows are the same `C0_V0`/`C4_V0` tokens F0-05 already found finance
never uses at all (extreme change + lowest volatility, consistent with volatility
clustering) — this isn't a new finding, just the same gap showing up again in a
different statistic. `C4_V1` sparse in finance (19 obs) is new: finance rarely pairs an
extreme-high change with low-but-not-lowest volatility either.

**This is exactly why A6 (ETT) needed a fixed `[0, 1]` colour scale instead of a
data-driven max.** ETT's `C0_V0` row has a single observation, and that one observation
happened to transition to `C2_V0` — so the row-normalised "probability" for that cell is
a mathematically correct but practically meaningless 1.0. It renders as the brightest
cell in the entire heatmap. A reader glancing at the figure without also checking
`transition_matrix_row_counts.csv` would read that as "C0_V0 deterministically
transitions to C2_V0," which is not a supportable claim from one data point.

## What this means for F0-07

F0-07's row-wise KL divergence must either exclude these 5 rows (2 ETT, 3 finance) or
weight them down — comparing a 1-observation row against anything else is comparing
noise, not signal. The row counts are already computed and saved specifically so F0-07
doesn't have to recompute them or, worse, silently include these rows at full weight
and let a handful of noisy cells distort the domain-similarity number the whole Phase 0
gate depends on.
